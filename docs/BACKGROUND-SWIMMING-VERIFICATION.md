# ブラウザの背後でも泳ぎ続ける設定（2026-09-30）

本人の希望に合わせ、Macの表示管理を `background-swimming-v2` に変更しました。ブラウザなどのウィンドウに覆われても、魚・水草・水のアニメーションを通常時と同じ24コマ/秒で続けます。魚の採用版は `bronze-gradient-guppy-v29-r16`、24匹・8色・Balancedです。導入前後で魚・素材・水景の設定とハッシュが一致しています。Windowsの設定と配布ZIPは変更していません。

## 現在の動作

| 状態（各画面ごと） | 描画 | ページの扱い |
|---|---|---|
| 画面の40%以上が見える | Balancedの上限24コマ/秒 | 保持 |
| 見える部分が40%未満、完全に覆われている場合も含む | 24コマ/秒 | 保持。60秒を超えても解放しない |

背後で停止していた以前の方式よりCPU・GPUの処理が増え、ページのメモリも保持します。12→24コマで描画回数は倍になりますが、CPU・GPU負荷やメモリが倍になるという意味ではありません。従来のr16測定値は今回の動作設定の数値ではありません。

## 現行24コマ版の導入と負荷比較

本人の「背後も24コマにしたい」という指定で12→24コマに変更し、2026-09-30 04:09に導入しました。ビルド・署名検査が成功し、旧アプリとLaunchAgentは保存退避しています。導入済みSwiftソースのSHA256は `c709172340a06cf8bbad60e21395ba6bd8a474c330e4c2c94ceeeefa7da70181`。魚・素材・水景の設定とハッシュは12コマ版と一致しています。

両画面を既存ウィンドウで覆った配置を保ち、12コマ版→24コマ版の順に約90秒ずつ測定しました。24コマ版の起動後には30秒以上の待機を置いています。`scripts/measure-r15.py` でアプリとそのWebKitプロセスのCPU時間差、プロセスごとの物理フットプリント、Mac全体のGPU使用率、SIGUSR2による実フレーム数を取得しました。

| 指標 | 背後12コマ | 背後24コマ（現行） |
|---|---:|---:|
| CPU平均（100% = 1コア） | 11.31% | 23.25% |
| GPU使用率中央値（Mac全体） | 32% | 40% |
| 描画用＋ページ用メモリ（最後の試料） | 914.3MiB | 900.8MiB |
| 外部画面の実描画速度 | 11.99fps | 23.99fps |
| 本体画面の実描画速度 | 12.00fps | 23.99fps |

この比較ではCPUは約2.1倍、GPU全体は8ポイント増加し、メモリはほぼ同じでした。CPUの23.25%はMac全コアの23.25%という意味ではありません。GPUには他アプリの処理も含むため、差を水槽単独の負荷と断定しません。メモリはプロセス間で共有する分を除いていない合算値で、今回の小さな減少を24コマ化による節約とは扱いません。各条件1回の短時間比較であり、普段のすべての作業や長時間の推移を保証する測定ではありません。

24コマ版では両画面とも2201コマ増加し、測定終了時も描画ループが動作中でした。記録は [12コマ版](../evidence/r15-load-background-12fps-before-24.json) と [24コマ版](../evidence/r15-load-background-24fps-after.json) にあります。本人の選択どおり24コマ版を稼働状態で残しています。

## 確認の限界と再確認

今回の24コマ版の導入後に手動Pause・低電力・実スリープ復帰・再ログインを実操作で再検証したわけではありません。停止条件は既存のままで、ページ解放機構は上記のネイティブ検査で確認しています。30分など長時間のメモリ推移は未実測です。

再確認する時は、ブラウザを画面の大部分に広げ、砂や水草が見える縁を残して75秒以上待ちます。背後の動きが継続し、診断の `loop.fps` が24、実フレーム数と魚・水草・水の時間が増えることを確認します。ブラウザを小さくしてもBalancedの上限24コマ/秒を維持する設定です。完全に停止したい場合はメニューバーのPauseを使います。
