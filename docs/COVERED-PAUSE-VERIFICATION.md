# 隠れた水槽の描画を止める設定（2026-09-30）

本人の省負荷運用の選択を反映し、Macへ `covered-pause-v1` を導入しました。魚は `bronze-gradient-guppy-v29-r16`、24匹・8色・Balancedを維持しています。導入前後で魚・水景の設定と素材ハッシュが一致しました。Windows版の処理は変更していません。

## 現在の動作

画面ごとに、水槽が見える割合を判定します。

| 水槽の見える割合・状態 | 描画 | 60秒後のページ |
|---|---|---|
| 15%未満（ほぼ隠れている） | 停止し、水槽の画像を残す | 解放する |
| 15%以上40%未満 | 12コマ/秒 | 保持する |
| 40%以上 | Balanced上限24コマ/秒 | 保持する |
| 画面／セッションの休止 | 停止 | 解放する |
| 手動Pause・低電力モード | 停止 | 保持する（画面／セッション休止も重なる場合は解放） |

ページを解放する前に、最大180万画素の不透明な水槽画像を取得します。取得できない場合は停止中のページを保持します。再び見えると画像の裏でページを読み込み、実際の初回描画後に画像を外します。長時間の被覆から戻った時は魚の位置が新しく始まります。元のmacOS壁紙・アクセシビリティ設定は変更していません。

## 実機での停止・表示保持

実際の2画面を既存ウィンドウが覆った状態で、SIGUSR2の受動診断を約75秒観測しました。描画を強制するSIGUSR1は使用していません。

| 画面 | 初回と約15秒後の累積描画数 | 約75秒後 |
|---|---|---|
| 本体 1665×1081 | 1 → 1、ループ停止 | ページ解放済み、水槽画像1512×982を保持 |
| 外部 1789×1006 | 1 → 1、ループ停止 | ページ解放済み、水槽画像1788×1006を保持 |

[受動観測JSON](../evidence/covered-pause-observation.json)に各状態を保存しました。CUAで導入済みアプリの水槽画像が残っていることも確認しました。取得画像は水槽ウィンドウ単体であり、ブラウザを重ねたデスクトップ全体の撮影ではありません。

## 実機での再開

Finderの「ほかを非表示」で外部画面を露出させ、終了後は「すべてを表示」で戻しました。元々非表示のアプリがないことを操作前に確認しています。

- 外部画面で2回、ページの再読込から実描画への切替を確認。所要時間は1.680秒と1.473秒でした。
- 2回目には累積描画数が1から85に増加し、魚・水草・水の時間も進みました。最後の受動診断は実測24.05コマ/秒、ループ動作中でした。
- ブラウザを戻すと0コマ/秒へ戻り、その後ページ解放と水槽画像の保持を再度確認しました。
- 本体画面はこの操作中も覆われていたため、今回の実機再開確認は外部画面についての結果です。

[再開観測JSON](../evidence/covered-pause-resume.json)にイベント時刻と描画数を保存しました。採取処理は診断ログを書き終えた後、一時的な `stats: null` の集計で失敗しました。保存済みの同じログをnull対応で再集計しており、成功していない採取を成功扱いにはしていません。

## 負荷について分かること・未測定のこと

ほぼ隠れた時の連続描画が止まり、60秒後には描画用ページが破棄されることを確認しました。これにより背後で12／24コマを描き続ける処理を省きます。静止画・アプリ本体・OSの画面合成は残るため、CPU/GPUやメモリがゼロになるという意味ではありません。ページ破棄はWebKitにメモリ解放を可能にしますが、プロセスの物理メモリ全量が直ちにOSへ返ることは保証しません。

この版では新たな90秒のCPU/GPU比較や30分のメモリ測定を行っていません。[以前の12／24コマ比較](BACKGROUND-SWIMMING-VERIFICATION.md)のGPU値はMac全体の値であり、この停止設定の負荷や削減量には転用できません。実スリープ復帰・再ログイン・低電力モードの実操作も今回改めて実施していません。

再確認は、ブラウザで画面の約85%以上を覆い75秒待つ → 水槽画像が残ることを確認 → ブラウザを小さくして魚が動き出すことを確認、の順です。一時的に常時停止したい場合はメニューのPauseを使用します。
