# 現在のGuppy水槽のCPU・GPU・メモリ使用量

2026年9月30日、このMacで測定しました。**ブラウザなどの裏で水槽が停止し、60秒後に描画用ページを解放した状態**の結果です。魚が見えて泳いでいる時や、Windowsでの負荷を示す数値ではありません。

導入前の過去の状態を再現することはできないため、「導入前相当」は水槽アプリと水槽用の全プロセスを終了した状態としました。アプリのファイルは削除していません。ほかのアプリやウィンドウ配置をこちらで変更せず、Guppyの有無を比較しました。

## 読みやすい要約

この設定では、停止中のGuppyに使われたCPU時間は**18コア全体の約0.01%**、水槽関係のメモリは**約91MB、搭載36GBの約0.25%**でした。CPUとメモリの常駐負荷は小さい値でした。

GPUはMac全体で、水槽なしの平均13.2%に対して、水槽ありでは平均19.0%でした。観測した差は約5.8ポイントですが、ほかのアプリの描画も含み、使用率の変動幅も大きいため、**Guppy単独でGPUを5.8%使っているとは断定できません**。停止中もアプリ本体・水槽画像・OSの画面合成は残るため、すべての負荷がゼロになるという意味でもありません。

## Mac全体の比較

| 項目 | 水槽なし（導入前相当） | 水槽あり（現在の停止設定） | 観測した差 |
|---|---:|---:|---:|
| CPU・全18コアに対する使用率 | 12.63% | 12.16% | −0.48ポイント |
| GPU・Mac全体の平均使用率 | 13.22% | 19.04% | ＋5.82ポイント |
| 使用中メモリ・概算 | 31.104GB / 36GB（86.40%） | 31.078GB / 36GB（86.33%） | −0.026GB（約−27MB） |

GB・MBはこの文書では1024換算（GiB・MiB）です。CPUの値は全コアのCPU時間に対する割合であり、異なる種類のコアの計算性能を同じとみなした性能占有率ではありません。メモリ全体は、回収可能なファイルキャッシュ等を除いた物理メモリ使用量の概算です。

水槽ありの方がCPU全体やメモリ全体の値がわずかに低いのは、ほかのアプリやOSの処理も変動するためです。Guppyを入れるとCPUやメモリが減る、という結果ではありません。GPUも同じ理由で、全体の差だけから水槽専用の負荷を切り分けられません。

## 水槽関係のプロセスだけの値

| 項目 | 水槽なし | 水槽あり・停止中 |
|---|---:|---:|
| CPU・全18コア換算 | 0% | **0.0114%** |
| CPU・1コアを100%とした表記 | 0% | 0.2045% |
| メモリ・プロセスの物理フットプリント合計 | 0MB | **91.2MB** |
| 搭載36GBに対する上記メモリの割合 | 0% | **0.247%** |
| GPU・水槽単独 | 対象プロセスなし | 単独の使用率は測定できていない |

対象はDeskworlds本体、専用WebKit GPU、専用WebKit Networkingの3プロセスです。描画ページ用プロセスは既に解放されていました。測定後に水槽だけを終了し、対象3プロセスがすべて終了したことを確認しました。

メモリは `ri_phys_footprint` のプロセス別の値を合計した参考値です。共有領域を重複排除した唯一の物理RAM占有量ではありません。したがって0.247%も搭載容量に対する参考比率です。OSの画面合成側に計上される負荷は、水槽プロセスだけの値には含まれません。

## 測定条件と限界

- Mac: CPU18コア、メモリ36GB、2画面。水槽は `bronze-gradient-guppy-v29-r16`、24匹・8色・Balanced、Mac表示管理は `covered-pause-v1`。
- 採用した測定は10:11 JST開始の「水槽あり→水槽なし」。各90秒、2秒ごとに45回採取しました。終了後15秒待ってから水槽なしの測定を開始しました。
- 水槽ありの開始・約30秒・約60秒・終了時に、両画面で0fps・ページ解放済み・水槽画像保持を確認しました。診断は描画を強制しないSIGUSR2を使用しました。
- GPUの中央値は水槽なし17%、あり19%。範囲は水槽なし0〜23%、あり0〜45%でした。平均値だけを水槽固有の増加量と解釈できない変動があります。
- 当初試みた露出状態の固定や、描画プロセスが途中終了した区間は採用していません。そのため、予定していた「なし→あり→なし」の3区間比較ではなく、上記の完全に採取できた2区間を報告しています。
- 他アプリを止めて隔離した試験ではなく、各状態1回の短時間測定です。温度・消費電力・電池持ち・長時間のメモリ増加は、この結果からは判断できません。
- 測定後は既存LaunchAgentで水槽を起動し直しました。LaunchAgentファイルが変更されていないことを検査しています。

現在の停止・再開の仕組みは [COVERED-PAUSE-VERIFICATION.md](COVERED-PAUSE-VERIFICATION.md)、以前の背後12／24fpsでの測定は [BACKGROUND-SWIMMING-VERIFICATION.md](BACKGROUND-SWIMMING-VERIFICATION.md) を参照してください。以前の値を今回の停止時の値と混ぜないでください。

CPU全体はMachのCPU時間差、GPU全体はIOAcceleratorの `Device Utilization %`、水槽のCPU・メモリは `proc_pid_rusage` から採取しました。メモリ全体の概算式は `(active + inactive + speculative + wired + compressor − file-backed − purgeable) × page_size` です。Activity Monitorとの完全一致を保証する値ではありません。

同じ設定・両画面被覆でページ解放を待ち、既存LaunchAgentが有効なMacで実行します。以下は測定中に水槽だけを一時終了し、最後に復元します。既存の出力先は上書きしません。

```sh
python3 scripts/measure-current-resources.py --run --condition covered --sequence on-off --output evidence/my-resource-measurement
```

画面が露出して泳ぎ始めたり、対象プロセスが変わった場合は、混ざった結果を正常な停止時の測定として採用せずエラーにします。停止中の安定した状態で再実行してください。
